# Infinite Practice Studio

Open **Math Center → Infinite Practice Studio** in the teacher app or local Content Studio. The same workspace is also available from **Teacher Study Hall → Practice & video studio**, **Manage practice & videos** on a math topic, and `/teacher/practice-studio`.

## Personal generator planner

Open **Math Center → My generator planner**, or use **My generator planner** from Infinite Practice Studio. This is a personal generator-building workspace, separate from student lessons and assignments.

- Choose **Add to planner** from a question-bank row, question inspector, selected bank questions, or a Math question in Student Progress / Student math insights. In the teacher app, pick an existing batch or create one without leaving the review screen. Content Studio carries the selection into the account planner to choose a batch. Repeated additions of the same source to a batch are deduplicated. **Create generator now** opens the single-question workshop with that source selected.
- Batches retain snapshots of the current canonical source questions, answer data, explanations, diagram references, source provenance, and classification. They do not copy student names, answers, or results. A missing source produces an error instead of substituting another question. The exported instructions require checking current sources before building.
- Name a batch, add shared instructions, then choose each question's existing destination module or name a new focused module under General Practice or Foundation Building. Individual requirements can describe variations and teaching concerns. Questions may span categories. Multi-select supports applying one destination to several related requests, and up/down controls reorder them.
- Edits autosave after a short pause. Requests are private to the authenticated teacher/admin account. The existing Math Command metadata adapter provides durable production storage, owner isolation, and revision-checked writes; no additional migration is required. Content Studio opens the authenticated account planner through its existing teacher-workspace launcher, carrying selected source IDs to the batch picker. It never writes a separate local planner. Existing local batches are retained in the metadata file; they are not automatically reassigned to another identity.
- The planner refreshes when you return to its tab, after a saved change in another tab, and periodically while visible. Background refresh preserves unsaved drafts, selection, and the question you are editing. Revision conflicts still require reviewing/reloading the saved version.
- The source's existing generators appear with review/enabled status and a preview action. Use this evidence to decide whether another generator is needed.
- **Copy full batch prompt** prepares one coding request. **Download plan** exports the versioned `nathan-tutors-generator-batch` JSON with source snapshots, stable request and module IDs, and build instructions. Select rows to export only those requests. **View prompt** supports manual copying. Export validates current destination IDs and classifications and marks only draft entries Exported after copying/downloading; review and student availability remain explicit teacher-set statuses.
- Duplicate a batch to reuse it with fresh request IDs and Draft statuses. Search and status filters help revisit saved work. Limits are 100 batches, 100 sources per batch, and 8 MB of saved planner content per teacher. Save failures retain the current draft and offer Retry, Reload, and a recovery download. Reloading with unsaved edits requires confirmation.

Module editing always exposes **Module name**, including focused modules and the two topic groups. Manually named modules keep their names when assigning or renaming a shared skill. Module IDs, selections, placement, and existing session snapshots remain stable.

General Practice and Foundation Building now use the same available topic library. Legacy parent placement is retained for stored IDs and organization; it does not restrict a mode's content. Both teacher group editors show all focused modules in the topic. Only Foundation Building exposes student settings to include or exclude published modules, plus an **Other question types** option for generators without a focused module. Hidden-only content and disabled generators remain excluded from the student catalog.

Foundation choices are saved per account and topic on the current device, separately from session snapshots. New modules are included by default. Shared generators stay included if any selected module contains them. **Resume practice** keeps the existing session's questions; **Start new with these settings** applies the saved choices and preserves the student's personal best. An empty selection cannot start a new session. General Practice has no student module settings and always starts with the full available topic library.

Verification: `npm run test:generator-planner` covers snapshots, duplicates, ownership, stale revisions, remote write failures, concurrency, batch exports, and module-name preservation.

## Create a custom code generator

1. Browse Math Center's question bank or full exam player and choose **Create infinite practice**.
2. Select the existing destination module, or name a new focused module under Foundation Building or General Practice. The brief preserves stable module and parent IDs, classification, the full source question, answer, explanation, and diagram references.
3. Add any requirements for difficulty, variations, diagrams, or interactions. **Copy coding brief** and paste it into your coding chat in this repository. **View coding brief** provides a manual-copy fallback.
4. The coding assistant implements a seeded TypeScript generator, checks its mathematics and rendering, and automatically enables it for practice modules in the shared catalog after validation. The batch and single-source briefs request the shared registration helper's `--enable` option. New generators stay unreviewed; existing review statuses and module publication settings are preserved. Copying the brief itself does not execute code, start a chat, or save a new generator.
5. After implementation and registration, reload the studio, find the generator, and **Preview a generated question**. Review its questions and explanations, enable it, publish a new module when ready, then **Save changes**. Hosted code must also be deployed before students can run newly implemented families.

Custom code can support diagrams and interactions through the existing question/player contracts, with renderer extensions when needed. It is not subject to the JSON template engine's 5,000-combination limit. Each family still needs an honest finite domain, repeat-cycle description, and tests appropriate to its mathematics.

The library labels compiled generators **Custom code**. Existing JSON generators remain playable and editable through **Edit or export JSON template**; the creation workshop now uses coding briefs. No existing catalog entries are automatically converted or removed.

The local Content Studio's practice adapter reads and writes the same `infinite_practice_catalog` table as the teacher app, using server-side Supabase configuration. It needs the same project and existing practice-catalog migration. A missing connection shows an error instead of creating a separate local practice library. Saves use revision checks and the editor's existing same-origin/edit-token protection.

## Recommended organization

Use the existing **category → subcategory → Skilled** taxonomy as the shared index for original questions and generators. Give focused modules short student-facing skill names, such as **Solving Two-Step Equations**. Keep source IDs as provenance rather than module names, and reuse several related generators within one skill module. One generator can serve more than one module without copying it.

Both modes use the same available topic library. Students customize **Foundation Building** by checking modules in settings; **General Practice** uses the full mix. Organize generators in focused modules so those choices are meaningful. Legacy parent placement and saved IDs are retained. Manage a generator through **Unreviewed → In review → Approved**, then enable it when ready; difficulty labels remain teacher judgments. The existing library filters expose unreviewed, disabled, and unassigned resources, while included generators appear first in each generation set with direct Edit and Preview actions.

Useful next extensions are a review queue showing validation evidence beside each source, student practice recommendations drawn from the separate English/Math evidence matrices, and progress by skill across original and generated questions. These are follow-on recommendations, not automatic placement or mastery decisions implemented by this workflow.

## Organize practice

### Shared Skilled classification

Math questions now have three organization levels: **Main category → Specific topic → Skilled**. Skilled is a teacher-managed registry, separate from diagnostic skills and freeform skill tags. Every saved individual practice module contributes its organization label to this list, including unpublished and empty modules. Manually defined skills are retained and matching labels are deduplicated within their subcategory. Existing and unassigned questions display **TBD**; question assignments are never inferred from module membership.

Open **Manage Skilled** beside a question’s Skilled selector, from a subcategory in **Manage categories**, from Math Command Center, or from Practice & video studio. Select the main category and specific topic, then add, rename, reorder, or delete skills. Changes are staged until **Save Skilled** and use revision checks to protect another window’s changes. Names must be unique within their own subcategory; TBD is reserved and always available.

Assign a question or generator using its Skilled selector. Bulk question classification and question/generator library filters also support Skilled. Changing a question’s category or specific topic resets its Skilled selection to TBD. Existing question wording, keys, and practice generators are preserved.

The selected shared skill supplies a focused module’s name, category, and subcategory. Selecting a skill replaces a draft or custom name, and skill renames update linked module names on reads and saves. New modules nest under Foundation Building; existing General Practice children are normalized to Foundation Building without changing IDs, generators, publication, or saved session snapshots. General Practice includes the same available modules automatically. Modules without a legacy classification still contribute their current names with stable module-backed skill IDs. Shared renames update the module labels. A skill used by a module cannot be removed independently: remove the module in Practice Studio first. Removing a module does not delete its generators or saved sessions.

Definitions persist in the existing Math Command management state and its durable metadata adapter, so no new database migration is required. Native source saves preserve the stable Skilled ID. Content Studio and the teacher app use the same durable metadata and practice-module projection by default. `MATH_COMMAND_STORAGE=file` explicitly opts into isolated local metadata for fixtures/offline work. Content Editor and module skill pickers refresh on focus/visibility and every 15 seconds while visible; stale native drafts are retained and require a reload before saving over changed classifications. New modules invalidate skill snapshots and catalog caches. No two-table synchronization or manual skill backfill is required.

### Generator library and focused skills

In a practice module's **Generation set**, use **Show generators → Included only** to see its selected, inherited, or automatically included generators, or **All generators** to browse eligible additions. Category and subcategory filters combine with inclusion and text search without changing the module's selection. Required topic groups stay scoped to their own subcategory. The shown count is separate from the module's full enabled-generator count.

**Preview example** beside any generator opens that generator in the floating question player directly from the Practice modules tab, including generators not currently selected. **Preview module question** uses the module's full effective draft generation set, including contained and automatic generators; list filters do not narrow the preview mix. Unpublished modules can be previewed, empty modules have the module-preview button disabled, and no preview saves catalog changes or student practice progress. Closing the player returns focus to the button that opened it.

Use **Question generators** to search titles, descriptions, IDs, skill tags, prerequisite skills, source question IDs, programs, and subjects. Filter by category/subcategory, enabled state, review status, difficulty, program, or subject. **No focused module** finds generators without a curated module assignment; automatic topic groups do not count as focused assignments. Sort by manual order, title, or review status. The library renders 40 matching generators per page; **Select all matching generators** includes every page.

Each generator has teacher-editable **Skills and review** metadata and a **Used in** list showing direct, automatic, and inherited module uses, including inactive and hidden uses. Program labels (SHSAT, SAT, PSAT, AP) and the subject are organizational metadata; they do not change enrollment, publication, or program routing. Difficulty starts **Unassigned** and review status starts **Unreviewed**. Prerequisites are planning notes, not access restrictions. Known built-ins receive their original source question IDs; unknown sources are left blank.

Select generators for bulk enable/disable, review status, difficulty, topic placement, skill tags, program, or subject changes. Changes remain drafts until **Save changes**. Bulk disabling hides focused modules left without any enabled generators; re-enabling a generator does not republish a hidden module. Moving generators retains explicit focused-module references; automatic groups follow the new category/subcategory. **Set program** replaces program labels; individual editing supports multiple labels. Validation rejects unsupported statuses, duplicate tags, invalid source IDs, and oversized metadata.

Each of the eight built-in probability generators belongs to one of these skill collections. General Practice supplies the topic-wide mix. These collections preserve the existing Foundation Building placement without asserting a difficulty progression.

Student choices for a split collection follow the new modules until the student configures them independently. Rerunning the preview after applying should report no changes. The catalog retains its existing limit of 1,000 generators and 1,000 modules.

**Dividing Symbolic Fractions** (`symbolic-fraction-division-v1`, source `2021-2022-form-a-q96`) is a disabled, unreviewed custom-code draft under **Algebra → Algebraic Expressions → General Practice**, using the existing stable module `general-algebra-algebraic-expressions-rj42ee`. Its finite domain is the 24 permutations of four distinct nonzero variables among two fractions, times two quotient directions: **48 distinct displayed stems**, all relabelings of the same reciprocal reasoning task. Each seed permutes that complete domain with stride 13, then repeats after 48 questions. Choice order is not counted as extra stems. There are no units or diagrams. Index 0 with the empty seed reproduces the original prompt, choices, and C key exactly. Distractors retain multiplication without reciprocation, inversion of the dividend, and grouping the symbols from each given fraction. Nonzero real values of either sign are allowed; numeric coincidences at particular assignments do not make different symbolic expressions identities.
