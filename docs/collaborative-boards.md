# Collaborative student boards

The feature is implemented in the existing React/Express application. On October 6, 2026, with explicit user approval, both learning-plan and board migrations were installed in the existing Nathan Tutors Supabase project (`juxcuposhxsmokqrszbh`) using `supabase/install-learning-features.sql`. All six feature tables passed the read-only readiness check, and the localhost student Boards library loaded without its storage error. Application deployment and full real-account collaboration acceptance remain pending.

## Entry points

- Teacher: **Boards** in the dashboard sidebar or overview opens `/teacher/boards`, listing their owned and invited boards across students. **New board** asks for a title and a student from the existing roster; creation adds the teacher as owner and that student as editor. The per-student **Boards** workspace remains available in Student Insights.
- Student: **Boards** in the existing student portal. Student-created boards start private; the owner can invite a verified teacher as editor or viewer.
- `/boards/:id` opens the canvas with a return link to the same student's workspace. Browser identity comes from the existing Supabase session; query parameters never authorize access.

## Canvas behavior

Wheel and trackpad pan; Shift+wheel pans horizontally. Ctrl/Cmd/Space+wheel and pinch zoom. Space/middle/right drag pans. The default select tool supports marquee, Shift selection, select-all, moving and resizing. Double-click empty space or click/drag the note tool to create a note. Double-click a note to edit Markdown; Escape or click away ends editing. Existing KaTeX rendering supports inline and display math. Longer notes grow as text is added and remain manually resizable.

The canvas supports text/math, image, file, link, group and linked educational cards; side handles; directional, labeled, colored and reconnectable edges; connect-and-create; spatial group movement; grouping/ungrouping; selection colors and layers; source locks; copy/paste/duplicate/delete; local undo/redo; find; fit-all/selection/reset; focus mode; and an optional minimap. Connectors use React Flow's compatible smart-edge library with worker-based obstacle routing. Groups do not obstruct connections between their contents.

Ctrl/Cmd+C/V/D/A/Z/Shift+Z, Delete/Backspace, Enter, Escape, Ctrl/Cmd+F, Shift+1 and Shift+2 operate on the focused canvas. Clipboard and editing shortcuts remain native inside the collaborative editor. Pasting text creates a note, a URL creates a link card, and an image uploads a private attachment. Cross-board clipboard copies containing private assets are rejected; **Duplicate board** copies those assets through authorized storage operations.

## Collaboration and safeguards

- Yjs maps store individual structural fields; each note has a `Y.Text`, bound to CodeMirror. Whole-string last-write-wins editing is not used. Undo tracks local operations and editor bindings, leaving independent remote edits intact.
- `/api/boards/live` authenticates the first WebSocket message using the existing Supabase session. Tokens are absent from URLs. Identities and presence labels come from authoritative Auth records. Cursor, selection, editing and drag previews are ephemeral. Viewer and locked-source rules also filter editing/drag presence on the server.
- Updates are batched for 240 ms. Moves and resizes persist final geometry; typing uses CRDT deltas. Server-to-client synchronization also uses deltas. Acknowledgements follow durable database commits.
- Temporary collaboration-service failures request automatic reconnect instead of forcing recovery. Failed internal rooms are discarded before a new join; cleanup from an old connection cannot remove its replacement room. Pending unacknowledged edits are retried, while reconnecting a clean viewer does not fabricate a pending edit. Permission and generation failures still require recovery.
- The server decodes and validates a candidate document, checks membership/viewer/lock rules (including shared-type identity) against the current database revision, stamps edit authors, checks asset ownership, and commits through an atomic SQL compare-and-swap function. Concurrent commits retry validation against the latest state. Incomplete causal updates are rejected into explicit recovery instead of being acknowledged unseen.
- Private Supabase Realtime channels fan out document notifications and presence between Express instances. Both channel reads and writes are denied to anonymous/authenticated browser roles for the internal topic prefix. If the fanout service fails, sessions reconnect rather than continue claiming synchronized collaboration.
- Membership, account archival and token validity are rechecked on writes and at 20-second connection heartbeats; membership changes trigger immediate room refresh. Owners can manage membership, archive, rename, checkpoint, restore and soft-delete. Explicit teacher editors and owners can lock source cards. Locked cards remain readable, selectable and connectable.
- Local IndexedDB recovery is scoped to authenticated user, board and generation. Temporary disconnections preserve local edits for merging. Restore snapshots the current version, regenerates the document and changes its generation; stale offline updates cannot overwrite it. Document generation is immutable for the client session and bound to the authenticated socket; metadata cannot silently relabel an older document. Permission/lock/version rejection offers an editable JSON recovery download and a reopen action.
- Automatic checkpoints are batched every five minutes of active changes. Named checkpoints and paginated history are available. Cursor movements never enter history. Viewport preference stays local to the browser.
- Student images/files use a private bucket, membership-checked uploads and 60-second signed URLs. Images have signature/type checks; other files download rather than execute. Board documents contain attachment IDs, not binary blobs.

Linked source cards resolve canonical passages, published question-bank questions, published assignments and accessible exam questions using the **board student's** access. Drafts, answer keys and explanations are excluded. Passage text is exported from the existing library at build time into `server/data/board-content.json`; board state retains stable references, not copies of the content database.

## Passage screens, annotations and layers

**Import exam passage** lists previously completed exam passages only, with title search, a result count and question counts. Completion comes from dated saved library attempts, compatibility library-attempt history, completed English exam passage results, or teacher-verified completed passage assignments. Assignment or an unlock alone does not qualify; in-progress work, math-only exams, and another student's history do not qualify. History queries paginate, and passage/set aliases resolve to the canonical library version. Completed custom exam passages retain their assessment reference. There is no content-type filter or individual-question/assignment import list. The server enforces this discovery scope; existing linked cards retain their authorized source resolution. Importing a passage creates a resizable mini exam screen with the original passage formatting, directions, every question, and response options/targets. The question selector and previous/next controls navigate the entire set. These are reference screens; answering and grading remain in the existing exam workflow. Nested dropdown, number-line and drag-slot answer keys are removed before export or HTTP delivery.

**Extract question** creates a separate movable question card with its original prompt and options plus collaborative **Reasoning & notes**. Drag its header to move it independently. The extracted card keeps a stable passage/question reference and the same student-content access checks. Selecting the new card no longer gets overwritten by the source card's click handler.

Select passage, question or note text and choose yellow, green, blue or pink in the card's highlighting toolbar. **Remove** clears highlights intersecting the selected text. Notes also support the editor's **Highlight** button and `==highlighted text==` Markdown. Shared highlight records merge through nested Yjs maps, obey viewer/source-lock rules, and survive reopening. Browser CSS highlights leave the React and KaTeX markup intact; ranges re-anchor when rendered content changes.

The selection toolbar has **Bring to front** and **Send to back**. The context menu and **Layers** panel also offer **Forward one** and **Backward one**. The panel lets users select covered cards. Layer ranks persist and synchronize; selecting/editing a card does not override its saved rank. Groups remain background frames.

These additions use the installed board schema and require no further database migration.

## Rollout

1. Both migrations are installed in Nathan Tutors (`juxcuposhxsmokqrszbh`). For another project, apply the learning-plan migration followed by `supabase/migrations/202610060001_collaborative_student_boards.sql`. They create the private tables, atomic functions, internal Realtime policies and private attachment bucket. Run `node tools/check-feature-storage.cjs` to verify table availability without reading student records. The combined installation file is for initial installation; do not rerun it after success because its policy definitions already exist.
2. Confirm actual teacher/admin identities have a trusted `app_metadata.role` of `teacher`/`admin`. Existing legacy `user_metadata.role` values are insufficient for privileged board access because users can edit that metadata. Use Supabase's administration tools to provision verified staff; do not automatically promote self-declared profiles. Other existing platform role helpers remain unchanged.
3. Set `CORS_ALLOWED_ORIGINS` to the deployed application origins (and the local Vite origin in development). Ensure the hosting reverse proxy supports WebSocket upgrades. Keep the service-role secret server-only. Enable private Supabase Realtime Broadcast for service-to-service channels.
4. Run `npm.cmd run verify` and `npm.cmd run test:boards`, deploy through the platform's normal process, then complete real-account acceptance below.

No new authentication system, public board link, anonymous sharing, periodic document polling or separate student roster was added. Optional templates, comments and PNG/PDF export are deferred.

The localhost check identified a separate role-provisioning issue: Nathan Im's existing account had legacy `user_metadata.role = teacher` and no trusted role. With separate explicit user approval on October 6, 2026, `tools/provision-nathan-board-teacher.cjs --apply` set that account's trusted `app_metadata.role` to `teacher`, preserving its other metadata. The teacher Boards workspace then loaded successfully in the existing authenticated localhost session. The repair script defaults to a dry run and refuses a different project, identity, or existing trusted role.
