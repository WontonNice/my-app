# Live game rooms

Teachers open **Game rooms** from the teacher dashboard. Students open **Game rooms** in the SHSAT portal and enter the six-character code. Teachers create and start both modes. Rooms, rosters, questions, scores, shared selections, timers, coins and sabotages persist in the database; browser refreshes and server restarts do not reset a game.

## Installation

Apply `supabase/migrations/202610240001_live_game_rooms.sql` before using this feature. It adds `live_game_rooms`, protected by RLS with no browser/anonymous table access. The existing service-role server connection handles authenticated API requests. No additional environment variables or third-party game service are needed. This migration was applied to the configured Nathan Tutors Supabase project on October 24, 2026; new environments still need it.

The server mounts `/api/game-rooms`. The client uses `GameRooms` for the teacher workspace and `StudentGameRoomsPage` at `/study-hall/shsat/games`.

## Solo teacher playtests

Choose either game, configure it normally, and select **Playtest solo** instead of **Create class lobby**. Survival starts with four simulated players; team races create two players per team and balance them automatically. Press **Start game** and answer as **You · Pilot**. No second account or student device is needed.

The **Play as** selector switches between the teacher view and any simulated player, including teammates and audience members. Opposing players move approximately every 12 seconds while the room is open. Toggle **Automatic opponents** off to control the pace, or press **Other players answer** for one simulation step. Bots leave your selected team under your control.

**Try a scenario** can submit a correct/wrong checkpoint, show a teammate's shared selection, or expire the timer. Open **Shop** or **Game controls & standings** to switch simulated players and use the **Sabotage test bench**. Party mode can be enabled during a private playtest. **Give my team 1 coin** funds the shared wallet. Buy an item, then use it from inventory and choose a team. **Test Ink Bomb on me** applies its real 30-second effect; click all seven splats to clear it early. **Test Landmine on me** traps the next question: submit the current question, then answer the next one correctly to disarm it or incorrectly to trigger a five-second blackout. **Restart playtest** clears scores, drafts, coins, inventory and effects and returns a fresh balanced roster to the lobby.

Both games render the existing `ExamSessionPage`, including its passage layout, navigation, math entry, highlights, pencil, notepad and review controls. The compact game bar opens standings and game controls. Math locks and scores on each question's **Next**. English retains answers across the complete passage and posts points only after its passage-completion screen. Teammates see draft changes within the passage. Ink Bomb and a triggered Landmine disable the exam surface. The server rejects answers, ready votes and purchases during either effect; ink cleanup remains available.

Only the original teacher host can access a playtest. Class students cannot join by code or access its test controls. Simulated players are excluded from student room membership, exams, analytics, and achievement progress. Answers and sabotage use the same server grading and transitions as class games; test controls cannot be enabled in an ordinary room. No additional migration is required.

## Last one standing

- The server takes a shuffled snapshot of published SHSAT Lab questions. At least three published questions are needed. Choose 3–50 questions; a smaller bank uses its available questions without repeats. Default round time is 90 seconds, adjustable from 15 to 600.
- At least two students join before the teacher starts. A round is one math/standalone question or a complete English passage. Passages stay together when sampled, so a requested question count can be exceeded to include a whole passage. Passage time is the configured seconds per question multiplied by its question count. A round reveals after everyone submits the checkpoint or its server deadline passes. Any missing or incorrect answer eliminates the player from the standing group; correct answers still earn individual points at reveal.
- Eliminated players remain in the audience, answer every subsequent question, and continue earning points. There is no knockout screen that stops their participation.
- The teacher advances after each reveal. When zero or one players remain standing, the next question is the final. If multiple players survive the entire question selection, its last question is still the final.
- In the final, correct standing players have priority. The highest-scoring correct finalist wins. If every standing finalist misses (or no one remains standing), the highest-scoring correct audience player steals the win. Ties share victory. If everyone misses, there is no champion.
- The teacher may end a room early; an interrupted survival game declares no champion.

The game uses an original classroom survival presentation. It includes no Jackbox artwork, sounds, scripts, or proprietary content.

## Team test race

- The teacher assigns an existing assessment, chooses 2–10 teams, and sets a 1–240 minute time limit (180 by default). All automatically graded question types are supported, including passages, multiple selection, numeric responses, matching, graphs and dropdowns. Tests containing essays are excluded with an explanation.
- After students join, assign individuals to teams or use **Balance teams**. Every student must have a team and at least two teams must be populated before starting. Empty teams are removed when the game starts.
- Teammates share their question position and answer selection. Selections autosave after a short typing pause. Every assigned teammate must vote ready before moving to the next question, including each question within an English passage. The ready panel names who has voted and who is waiting. Students can withdraw their vote; changing a saved answer clears all votes. Only active teammates count. Disconnected students remain active and can reconnect. During a race, the host can use **Someone leaving early? → Mark left class** to excuse a departing student, or **Restore player** when they return. Excused students remain in the roster with a Left class label, keep their scores and team history, cannot change answers, vote or use inventory, and are excluded from ready votes and cursors. A participation change clears that team's ready votes and invalidates stale ballots while keeping saved answers. Teams with no active students cannot be targeted and do not block completion by the remaining teams. Duplicate or stale votes cannot advance twice.
- English passages have a shared review screen. Everyone votes again to submit the complete passage and post its points. Teammates can return to earlier questions for review; moving forward still requires unanimous approval. Answers in a submitted passage or math question cannot be changed.
- Named, colored cursors show teammates' live mouse positions on the exam surface. Positions are anchored to the displayed question/passage and normalized for different window sizes. Cursors are temporary, disappear on departure, and reconnect automatically. Opposing teams cannot see them.
- The host selects **Watch Team** from the overview or standings to open that team's live, read-only exam page, including shared selections, question position, ready votes and cursors. The team selector switches views without impersonating a student. Both the overview and in-exam standings list the students on every team.
- Each correct question earns one point, regardless of question weight. Math points post per question; English passage points and streaks commit together when the complete passage is submitted. An incomplete or stale checkpoint cannot partially change scores. Teams can proceed at different speeds; the live standings show score and the current checkpoint's first question. Students see their team's previous correctness and streak; opponents' draft choices remain private during play.
- The highest score wins when all teams finish, the time expires, or the teacher ends the race. Unanswered questions earn no points. Ties share victory; speed does not break a tie.
- Optional **Party mode** awards **1 shared team coin** for every three consecutive correct answers (3, 6, 9, etc.). A wrong answer resets streak progress but keeps earned coins. Coins are banked without an inventory cap. The in-exam **Shop** shows the wallet, progress to the next coin and two purchases costing **1 coin each**. Buying stores the item in the shared **Team inventory**, without choosing or affecting a target. Press **Use Landmine** or **Use Ink Bomb**, then choose a team from a picker displaying team names and student rosters. Cancel keeps the item. Only a successful use consumes one item; invalid or unavailable targets leave inventory untouched. Earning new coins and buying other items do not erase inventory.
- **Landmine:** secretly traps the opposing team's next question after the one currently shown. The trap remains hidden from all student API responses. A correct graded answer disarms it; a wrong one causes a **5-second blackout** naming the attacking team. For English passages, the trapped answer resolves when the complete passage is submitted, preserving atomic passage grading. A team on its final question has no next question to trap.
- **Ink Bomb:** replaces the old direct Blackout purchase. Seven ink splats cover the whole team's screens for up to **30 seconds**. Any teammates can click the splats; their shared cleanup persists on the server. Seven distinct splats clear the effect early. Duplicate clicks count once, stale bomb IDs cannot clear a newer attack, and refreshes do not reset its timer. The attacking team is named.
- A team can have only one pending or active sabotage at a time. Completed teams cannot buy or be targeted. Invalid purchases do not spend coins; failed uses do not consume inventory. All penalties, purchases, clicks, attribution and timers are enforced and persisted on the server.

Games do not submit ordinary assessment results, change exam access, or award test achievements. Their scores represent the separate multiplayer activity.

## Adding shop items and ending rooms

`GAME_BOOSTERS` in `server/src/shared/gameRooms.ts` defines shop IDs, names, descriptions, prices and durations. `GAME_COIN_STREAK` defines the earning cadence. `server/src/lib/gameBoosters.ts` handles wallet updates, purchases, inventory use, ink cleanup and trap resolution. Shop cards and playtest buttons use these definitions. Existing unused Blackout rewards convert one-for-one into coins. Room JSON stores the new fields, so no database migration is needed.

**End room** and **Delete room** archive the room with `closedAt`. It immediately disappears from the host's list, and connected students return to their room list on the next poll. Archived IDs and join codes cannot reopen it. This is a reversible database archive, not a permanent record deletion; there is no restore button. Normally completed games show final results to connected participants and are omitted from recent-room lists.

## Persistence, access and operational limits

- Every request verifies current Supabase identity, role, enrollment and archived status. Students must be active SHSAT members. Only the original teacher host controls a room. Join codes allow students into a waiting lobby; only existing members can reconnect after it starts.
- Rooms support up to 100 students. The recent list shows up to 30 joined/hosted rooms. There is no automated retention/deletion job in this version.
- Active room clients poll every 1.5 seconds; the host's selected team view polls every second. Browser network throttling may delay visual updates, but server deadlines, unanimous votes and scores remain authoritative.
- Cursor updates use authenticated WebSockets at `/api/game-rooms/live`, throttled to ten updates per second per client. The server relays them across instances using private Supabase Realtime channels, as boards already do. No new migration is needed. The browser does not join internal broadcast channels. Room membership and host observation permissions are verified on connection and periodically afterward; cursors are scoped to teammates and the observing host. The Vite proxy forwards this WebSocket path locally.
- Room updates use database revision compare-and-swap, retrying conflicts up to 12 times. The same protections cover joins, shared answers, team progress, shop purchases, inventory use, attendance changes and ink cleanup. Future question content and nested answer keys are removed from client responses; only the current checkpoint is sent. Single-question survival keys/explanations appear after the round closes.
- Deadlines are evaluated on room reads and actions. If everyone disconnects, the first reconnect finalizes the expired round/race before accepting another answer. The host can reconnect through their recent room list; teachers must advance survival reveals.
- A game snapshots source content when created, so later edits to the question bank or assessment do not change an ongoing game. No participant emails are exposed to other players.
