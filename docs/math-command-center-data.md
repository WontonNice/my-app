# Math Command Center data and validation

The Command Center is an index over the existing Math content. It reads `server/data/exam-content.json`, which the existing export process produces from the Content Studio exam sources, and Math records in `server/data/question-bank.json`. Question IDs remain the references used by exams, student results, and assignments. Collections contain IDs only; they do not copy question content.

`server/data/math-command.json` is the metadata and preferences sidecar for local authoring. The local development API shares it by default. In production, or with `MATH_COMMAND_STORAGE=supabase`, the authenticated API uses the singleton `math_command_metadata` row in Supabase. Both modes store teacher-entered classifications, diagnostic skills, secondary skills, difficulty, source labels, standards mappings, inventory targets, saved filters, collection references, configurable evidence rules, and a bounded undo history. Neither is a second question database. Question wording, answer keys, diagrams, explanations, existing results, and assignments retain their existing authoritative stores. A native Math Editor save can persist its current category and subcategory back to the source and retire the corresponding local overlay.

Hosted metadata is durable across deployment and instance replacement. Each API request reads its remote metadata revision into an isolated context, and mutations must pass a database compare-and-swap before returning success. Remote mode never falls back to local file writes. The initial remote row may be seeded from the published sidecar; after it exists, the remote row always wins, so redeploying older local metadata cannot overwrite hosted work. Local Content Studio and hosted metadata are separate publication states, with no automatic two-way synchronization. See [deployment setup](math-command-center.md#deployment-and-durable-metadata) before first use.

Bulk edits require a preview of the exact IDs and fields. Preview tokens are bound to the workspace, teacher, metadata revision, selected source content, and a fifteen-minute expiry. Applying edits writes only permitted metadata. Undo refuses to overwrite newer edits to those questions. Separate local Content Studio and API processes use an exclusive file lock around revision checking and atomic replacement; a competing save returns a retry message. Native editor saves require the loaded metadata revision, recheck it before writing content, and preserve newer overrides if management metadata changes while a source save is in progress. A leftover `.lock` after an abnormal process termination requires an operator to confirm that no writer is active before removing it.

The normal content exporter writes `server/data/math-import-review.json`, containing only canonical IDs that still need editing. Production can preserve those red-import readiness flags without publishing private import drafts, original source documents, or diagnostics. Local explicit status updates take precedence; if a shared question has several source statuses, any active needs-editing status keeps it in review.

Readiness is explicit and conservative. Missing category, subcategory, difficulty, source, answer key, explanation, a required diagram, invalid interaction keys, unsupported classification, import draft status, and unresolved duplicate warnings enter the review queue. Marking duplicate review complete does not publish an imported draft. Readiness checks identify structural problems; they do not prove that the written explanation or keyed answer is mathematically correct. Numeric duplicate-choice checks use exact rational literals rather than floating-point approximation or an algebra solver.

The five categories and twenty-three subtopics come from `tools/math-topics.json`. The forty-one starting diagnostic skills and their prerequisite links are an editable organizing vocabulary; no questions receive these skills automatically. Prerequisite links indicate what evidence to inspect and do not establish a student's weakness by themselves.

The standards reference catalog provides Grade 7 and 8 domain references to the [NYSED Next Generation Mathematics Learning Standards](https://www.nysed.gov/sites/default/files/programs/standards-instruction/nys-next-generation-mathematics-p-12-standards.pdf), also listed on [NYSED's mathematics resources page](https://www.nysed.gov/standards-instruction/mathematics-guidance-resources). These references are navigation aids. No question-level standards mappings are pre-verified. A teacher must explicitly mark a mapping as verified and provide an HTTPS reference; the software records that review rather than asserting it independently. Diagnostic skill defaults contain no automatic standards mappings.

Inventory targets start at ten ready questions per subtopic and difficulty and can be changed by the teacher, including setting a target to zero. These are planning preferences, not an official SHSAT distribution or a prediction of exam coverage. Coverage counts include configured subtopics with zero inventory. Unknown difficulty remains unclassified; absent student performance remains unavailable instead of becoming a fabricated zero.

Duplicate checks preserve mathematical signs, variable case, numeric values, answer-choice content, interaction structure, context, and image references. Exact groups identify matching normalized content; answer keys still need comparison. Template groups identify matching wording with changed numbers and are distinct practice variants. Possible groups use source-identifier conflicts and a bounded rare-token search with at least ninety percent token overlap. The possible-match search is deliberately bounded for large libraries and is not a proof of uniqueness. It does not compare image pixels, delete records, merge attempts, or reclassify content.

Catalog filtering, sorting, pagination, coverage, duplicate matching, and rules run deterministically. Local metadata operations need no network; hosted persistence and existing student records use the application's ordinary Supabase database. No mode requires a model, embedding service, or AI key. Tests exercise a five-thousand-question catalog and temporary canonical fixtures, including thirty-question edits, source preservation, preview/undo concurrency, durable restart/CAS behavior, settings validation, and a network-disabled local management flow. Browser verification of the integrated teacher and student workflows is a separate release check.
