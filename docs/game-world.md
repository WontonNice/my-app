# 3D World in Game Rooms

The 3D island is a mode in the existing **Game rooms** screen. It uses the same signed-in teacher/student accounts, room codes, recent-room list, and host controls as the other classroom games.

## Open and join

1. The teacher opens **Game rooms**, selects **3D World**, gives the room a title, and selects **Open 3D world**.
2. The teacher can enter immediately and share the six-character room code.
3. Students enter that code in their existing **Join your class** form, choose a character, and enter the same island. Students can join while the world is open.
4. Returning participants reopen the room from their recent-room list. The host ends the room when the class is finished.

This mode does not require an assessment or question bank. It does not submit exam results or change assessment scores. The teacher explores as a real participant; the world does not populate itself with simulated students.

## Characters and interaction

The wardrobe has ten characters: Tung Tung Tung Sahur, LeBron · Le Sunshine, Mike Wazowski, Pepe the Frog, Astronaut, Frog, Mushroom, Alien, Wizard, and Duck. The four new models follow the supplied references: Sahur's wooden cylinder, large eyes and bat; Mike's round lime body, single turquoise eye, horns and toothy grin; and Pepe's broad eyes, orange lips, blue shirt and red shorts. Le Sunshine uses the supplied portrait intact as a texture projected onto the curved front of a 3D head, with a golden aura and basketball outfit. These are animated procedural interpretations, not imported film/game meshes. The original six characters remain available. The wardrobe scrolls to fit the expanded roster.

Students can walk with WASD or arrow keys, jump with Space, orbit the camera by dragging, and zoom with the mouse wheel. Touch controls are available in the world view. Preset wave, dance, cheer, and hello interactions are visible to other connected participants. Display names come from the authenticated classroom accounts.

Choosing an emote returns keyboard focus to the world. Walking or jumping immediately cancels it, with no extra click or stop button. Escape or selecting the same active emote also cancels it. Cancellation is shared with other participants. Arm poses extend outward so the hands remain visible around each character's costume.

## Teacher playtesting

The room's teacher has **Play**, **Spectate**, and **Playtest** choices above the world. Play is the default. Selecting Playtest enables admin controls and **Add test buddy**. This adds a clearly labeled extra character beside the starting area. Use **My character** and **Test buddy** to switch control; each keeps its position and outfit. The usual movement, jump, character selection, and emote controls operate the selected character. The other character waits where it was left. Use **Remove test buddy** to dismiss it. Leaving Playtest removes the buddy from the defense and hides admin controls. These modes use the current room, and playtest changes affect its shared game.

**Spectate** joins the teacher as an observer and keeps their host priority, including the ability to choose questions, start, end, and reset an expedition. Spectators do not need to ready up, receive items, count toward waves or the team shield, or answer monsters. They have no visible avatar in the scene. Use WASD or touch movement to pan the free camera, drag to orbit, and scroll to zoom; the camera menu can follow a connected student. The teacher can switch back to Play at any time. An unfinished question resumes if its monster is still available. Spectators alone do not keep an empty battle moving. The selected teacher mode persists across reconnects and new expedition setup.

The buddy is visible to everyone in the room but does not count as a student, occupy a student seat, or create assessment records. Only the room host can create one. Its connection uses the host's existing sign-in, with a separate server-assigned avatar identity, and closes when the teacher leaves the world. Ending the room also disconnects it.

## Crystal Defense

Crystal Defense is a game inside the same world. The glowing gate on the island opens its waiting lobby; the **Crystal Defense** button also enters that lobby. The game host chooses **Math · Exam questions** (all exams or one exam, with category and subcategory filters), **Math · Infinite practice**, or **Reading · SHSAT Lab** (published reading questions, optionally filtered by skill). The finite question set is dealt from shuffled index decks and recycled after each pass; the source question array stays stable while monsters reference it. There is no wave limit or automatic victory when questions run out. Play continues until the crystal is destroyed or the host ends the expedition.

Infinite practice uses the same generator and module registry as the math practice area, including **Foundation Building**, **All Question Types**, and **One-step Inequalities**. Select a module, math category, and optional subcategory. Category counts represent available generator types, not a finite question pool. Each new monster, including reinforcements, receives a generated variation based on the expedition and encounter sequence. The current generators cover inequalities; new registered generators appear automatically in matching modules. Variations may repeat in long sessions. A monster's generated question and answer key stay fixed through retries, disconnects, and teammate rescues. Unreferenced question slots are reused so long expeditions do not retain an ever-growing question history. Answer keys and explanations remain outside player snapshots.

The first student entering the defense lobby becomes its game host. The room's teacher takes priority whenever they enter, including during an ongoing battle. The host's 3D name tag has a gold crown that transfers with the role. If the host leaves or goes offline, the earliest remaining online student takes over; the teacher always takes priority when present. Test buddies never become host. This game role allows question selection, starting, ending, and resetting Crystal Defense; it does not grant teacher access or room moderation powers.

Defenders mark themselves ready after the host chooses questions. The host starts once everyone online is ready, transporting participating characters to the crystal arena. The teacher and test buddy can join as separate defenders for playtesting. Students who stay on the island wait for the next lobby; the teacher can enter an ongoing battle to take over hosting.

Walk within 3.5 world units of a monster and click it, press **E**, or choose it from **Monsters**. The question opens with its full passage or math response controls, and that monster freezes under a shield while the student solves. Other monsters keep walking. The player must answer before choosing another monster: the question has no release button, and the server rejects attempts to release it or switch targets. Correct answers defeat the monster and award exactly 100 personal and team points. A wrong answer normally releases the monster at its current position, where it resumes walking toward the crystal with an **!** above it; that student cannot retry it, but another defender can. A collected retry token grants one exception on the player's next question, described below. The crystal starts with five hearts and loses one only when a monster physically reaches it, including when everyone has already failed that monster. The HUD and question panel show remaining hearts; personal scores and total team points stay visible in the arena.

### Player count and tempo

There is no answering countdown. Every unchallenged monster walks continuously, while the particular monster being answered stays frozen. Every wave has more monsters than defenders, and all of them appear immediately. There are no reserve monsters or delayed encounter releases.

Each wave initially spawns `min(160, P + ceil(0.25P) + (wave − 1) × max(1, ceil(0.2P)))` monsters, where P is the online defender count at wave start. Four defenders face 5, 6, 7, 8, and 9 monsters in the first five waves, then 14 in wave 10 and 24 in wave 20. Solo games start with two and add one each wave. Enemy counts keep rising after movement reaches its speed limit, creating an increasingly overwhelming survival challenge; 160 initial enemies is the scene's performance cap.

If an online defender is not solving and has no eligible available target, a reinforcement appears after 12 seconds. Target matching accounts for other players' claims and each player's failed attempts, so a solo tester or fast finisher gets another question without waiting for old monsters to reach the crystal. Reinforcements appear directly on the field; old monsters continue walking. Completed monster records are removed after their animation window, and every new encounter has a unique identifier.

Normal crossing time starts at 150 seconds in wave 1, decreases by 10 seconds per wave, and reaches its 100-second minimum in wave 6. When every online defender is solving, a visible team shield halves the walking speed of unchallenged monsters. They continue moving, while students averaging two minutes per question still have a chance to rescue the remaining enemies. The HUD distinguishes normal crossing time from the shield's effect. Wrong answers do not teleport enemies, immediately deduct hearts, or remove monsters that have no eligible rescuer. Those monsters keep walking until arrival. A challenge can pause its own monster indefinitely; ending the challenge resumes its remaining journey.

There is a five-second regroup interval between waves. Participants send a heartbeat every 15 seconds, including while solving. After 60 seconds without contact, their challenged monsters are released and host eligibility updates. The unanswered assignment survives that release: reconnecting automatically resumes the same monster if it is available. If a teammate is solving it, the returning player stays assigned until it becomes available or is resolved. This prevents reconnecting to browse for an easier question without freezing abandoned monsters. Assignments clear when the monster is defeated, reaches the crystal, or is replaced by a new wave. Explicitly leaving still prevents rejoining an ongoing battle. Losing defenders slows movement in proportion to the reduced roster; monsters remain on the field. When the entire team is offline, movement and new waves pause. Ending or resetting the expedition returns everyone to its waiting lobby while keeping the shared world open.

### Wave items

Each wave starts with one personal item for each online defender, placed randomly on the reachable arena floor. Walk within 1.5 units to collect it automatically. Items are reserved for their owner, and each defender can collect only one per wave. The server enforces identity, ownership, the per-wave limit, finite reported coordinates, and pickup distance atomically. Like existing avatar movement, reported positions originate at the client. Reconnects and rejoining do not create more drops. Late arrivals receive their first drop next wave. Uncollected items remain available during the five-second intermission and are replaced at the next wave.

- **Speed potion:** adds 10% to walking and sprinting speed for this expedition. Three potions reach the 30% cap (walking 4.8 → 6.24 units/second, sprinting 7.2 → 9.36). Further waves offer retry tokens to players already at the speed cap. Bonuses apply in the arena and reset with a new expedition.
- **Retry token:** stores one token for the next question the player opens. It binds to that question on claiming; the first wrong answer consumes the extra attempt while the monster stays frozen and the answer form clears. A second mistake releases the monster and locks that player out as usual. A correct answer still awards exactly 100 points. Leaving or disconnecting until the claim expires discards the attached extra attempt. Stored tokens do not stack beyond one.

The item HUD shows movement bonuses, stored retries, and whether the current wave's item was collected. Each answer attempt has a private identifier that changes when a retry is granted, preventing duplicate or concurrent submissions from spending both attempts. Item collection and answer rewards remain atomic across server instances.

### Teacher controls

Only after selecting **Playtest**, the room's teacher can open **Teacher controls** directly from the arena HUD without selecting a monster. Controls also appear in Game details, the question dialog, and the defeat screen while Playtest is selected. Jump directly to a numbered wave (1–9999), advance to the next wave, restore five hearts, or destroy the crystal to test the actual defeat screen. These controls change the shared expedition and remain available while controlling a test buddy. When both characters are connected, the question dialog also lets the teacher switch between their character and the buddy while keeping each monster claimed. Student game hosts do not receive these controls. The server rejects admin actions outside Playtest, including stale requests from another tab.

Jumping requires a configured question source and an online defender, but bypasses readiness for testing. It replaces current encounters, closes outstanding questions, and keeps points, speed bonuses, and unspent retry tokens. The selected wave gets fresh item drops and a fresh pickup allowance. A jump after defeat restores five hearts; restoring hearts alone does not revive a finished battle. Every jump creates a new run identifier so delayed submissions or pickups from the previous wave cannot affect the new one.

### Crystal Defense implementation and checks

Configuration, host election, readiness, claims, attempts, points, hearts, wave scheduling, and run identifiers use the existing durable room payload and atomic updates. Walking positions are projected from server timestamps; ordinary movement polls do not write a new room revision. Actions, changes in movement rate, and arrivals persist a new baseline. The scene anchors server time to a monotonic browser clock for smooth movement without relying on device clock accuracy. Question keys stay server-side; only the current claimant receives a sanitized question. Duplicate submissions cannot award points twice, and stale answers cannot affect a new expedition. The 3D scene enforces approach distance; the server does not yet verify avatar proximity when claiming through the API.

Run `node --test server/tests/crystal-defense.test.cjs server/tests/crystal-sources.test.cjs tools/crystal-scene.test.cjs tools/crystal-panel.test.cjs` for focused checks, alongside existing world, avatar, survival, and team-game coverage. ## Runtime

The scene loads on demand when a 3D room opens. Three.js renders the island and avatars in the browser. A browser/device with working WebGL is required; graphics are drawn locally, so performance depends on the student's device.

Movement and interactions use an authenticated WebSocket at `/api/game-rooms/world`. The Vite development server proxies that path to the existing Express server on port 8080. Production hosting must support WebSocket upgrades on the same path. Private Supabase Realtime channels relay temporary presence across server instances, using the same server-side service as existing shared game cursors. Room creation, joining, and host actions continue through the existing game-room API. Temporary connection retries preserve the browser's position; reopening or reloading the page respawns the character. The room's durable membership uses the existing room store. Refreshed sign-in tokens reconnect the world automatically.

Each room supports the host plus up to 31 students. Position snapshots are batched at 10 Hz; clients interpolate other players' movement. Opening the same participant in another tab transfers that participant's avatar to the newer connection. Removed students cannot use the same room code to rejoin that world. The teacher's **End room** control closes it for everyone.
